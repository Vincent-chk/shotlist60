# ShotList60 · 干货稿 → 60 秒口播分镜，附一个「数字审计员」

[![audit](https://github.com/Vincent-chk/shotlist60/actions/workflows/audit.yml/badge.svg)](https://github.com/Vincent-chk/shotlist60/actions/workflows/audit.yml)

把一篇知识类干货稿交给火山方舟上的 Doubao-Seed 深度思考模型，一次调用改成能直接拍的 60 秒口播分镜（JSON），然后用几行代码把最容易翻车的地方**机器核对**一遍：

- 镜头秒数加起来是不是正好 60
- 每一镜的台词念不念得完（4-5 字/秒）
- 口播里的**每一个数字**，原稿里有没有——知识类账号最怕的就是模型顺手「编一个」

纯 Python 标准库，零依赖。没有 API Key 也能用：把提示词粘到方舟控制台，把回复存成文件，审计器照样审。

## 为什么要有审计员

让模型写短视频脚本不难，难的是你要**逐镜核对**：11 个镜头的秒数加对没有、每镜多少字几秒钟、口播里冒出来的「90%」「8 小时」到底是原稿写的还是模型发挥的。一条 60 秒的脚本，核对点轻松超过 30 个，肉眼看一遍五分钟，看十条就想放弃。

所以这个仓库做了两件事：

1. **一条提示词**：让模型按固定 JSON 结构输出，并把「秒数和=60」「数字只能来自原稿」「4-5 字/秒」写成硬性要求。
2. **一个审计器**（`verify.py`）：既然是 JSON，这些要求就能用代码精确核对，不再靠眼睛。

```
 干货稿 ──► prompts/v2.md ──► Doubao-Seed 深度思考 ──► 分镜 JSON ──► verify.py ──► 审计报告
 (sources/)                  （方舟 API 或控制台粘贴）                           PASS / WARN / FAIL
```

## 快速开始

```bash
git clone https://github.com/Vincent-chk/shotlist60.git && cd shotlist60
make test     # 审计器自测（14 个用例）
make audit    # 复验仓库里记录的 3 条真实运行，不需要 Key
```

### 路线 A：有方舟 API Key，一条命令跑完

```bash
export SHOTLIST_API_KEY=你的方舟Key          # 也接受 ARK_API_KEY；只从环境变量读，不进代码不进产物
export SHOTLIST_MODEL=doubao-seed-1-6-250615  # 换成你开通的任意 Seed 深度思考模型 ID
python3 run.py --source sources/coffee.md --out runs/demo
```

`run.py` 会调用方舟的 OpenAI 兼容接口（默认 `https://ark.cn-beijing.volces.com/api/v3`，深度思考默认开启），把回复解析成 `shots.json`，立刻审计，产物全部写进 `runs/demo/`。审计未通过时退出码为 1，方便接到脚本或 CI 里。

### 路线 B：没有 Key，粘贴两步走

```bash
python3 run.py --print-prompt --source sources/coffee.md     # 1. 打印完整提示词，粘到方舟控制台或任意对话窗口
python3 run.py --from-response reply.txt --source sources/coffee.md --out runs/demo   # 2. 把模型回复存成 reply.txt 喂进来
```

回复带 ```` ```json ```` 围栏、前后有客套话都没关系，会自动抽取 JSON。

### 只审不生成

```bash
python3 verify.py --source sources/coffee.md --shots runs/2026-10-18-coffee-v1/shots.json
```

`--shots` 可以是整理好的 JSON，也可以直接是模型原始回复。

## 审计规则

| 检查 | 规则 | 失败 | 警告 |
|---|---|---|---|
| 结构 | 六个顶层字段齐全，每镜有 `no / visual / narration / seconds` | 缺字段、类型不对、台词为空 | 镜头数不在 6-20，标题超 30 字 |
| 时长 | 秒数合计 = `total_seconds` = 60 | 合计不等于 60；单镜不在 2-15 秒 | — |
| 语速 | 每镜「念出来的字数 ÷ 秒」，理想 4-5 | 超过 6.5 字/秒（基本念不完） | 低于 3 或高于 5.5 |
| 钩子 | 3 秒内念完 | — | 超过 20 字 |
| 数字溯源 | 标题、钩子、口播里的每个阿拉伯数字都要能在原稿找到 | 任何一个数字原稿没有 | — |
| 中文数字 | 「两千年」「一九零零」这类机器溯源不了 | — | 出现即列出，请人工核对 |
| 数据点 | 去重后至少 3 个原稿数字被保留 | 少于 3 个 | — |

**字数怎么算**：汉字、字母、数字各算 1 个，标点空白不算。5 位以上的长数字按中文读法估——`2147483647` 念出来是「二十一亿四千七百四十八万三千六百四十七」，算 18 个字而不是 10 个；年份、三位数仍按 1 字/位。

**数字怎么比**：`5.0`、`05`、`1.40` 先归一成 `5`、`5`、`1.4` 再比，画面描述（`visual`）里的数字不查，因为不念出来。

## 三条真实运行记录

`runs/` 下保留了提示词、原始回复、解析后的 JSON、审计报告和元信息，`make audit` 会把它们全部重审一遍，CI 每次推送也会跑。

| 记录 | 原稿 | 提示词 | 结果 | 说明 |
|---|---|---|---|---|
| `2026-10-18-coffee-v1` | 咖啡因 6 个数字（851 字） | v1 | 0 失败 / 0 警告 | 8 镜，每镜 4.43-5.00 字/秒，15 处数字全部溯源成功 |
| `2026-10-18-y2038-v1` | 2038 年问题（999 字，数字密度高） | v1 | 0 失败 / 3 警告 | 暴露审计器两个盲区（见下），镜头 8 偏快，钩子 22 字 |
| `2026-10-18-y2038-v2` | 同上 | v2 | 0 失败 / 1 警告 | 钩子 12 字，中文数字 0 处，长数字镜头给到 8 秒；剩一条英文计数偏严的警告 |

### 第二篇稿子教审计器学会的两件事

第一版审计器在 `y2038-v1` 上全绿，但对照原始回复发现它漏了两处：

- 镜头 2 写成「两千年被当成一九零零年」——全是中文数字，溯源器一个阿拉伯数字都没抓到，等于「没查」却显示通过。现在会把中文数字单独列出来提醒人工核对。
- 镜头 4 的「2147483647」按 10 个字算、7 秒镜头 4.71 字/秒看着很舒服，可念出来是 18 个音节，实际 5.86 字/秒。现在长数字按中文读法估音节。

对应地，提示词 v2 比 v1 多了三条：数字一律用阿拉伯数字照原稿写法抄、长数字按念出来的长度配秒数、钩子 20 字以内。`y2038-v2` 的结果就是这三条生效后的样子。

### 三条记录是怎么产生的

三条记录都是走**路线 B**（`meta.json` 里 `mode = from-response`）审计入库的：提示词由 `run.py --print-prompt` 渲染，回复原文存在各自目录的 `raw_response.txt` 里，没有做任何手工修改。

## 口径与已知局限

- **4-5 字/秒、6.5 失败线**是中文口播的经验值，不是测出来的物理常数；换成英文或快节奏账号请自己调 `verify.py` 顶部的常量。
- **数字溯源查的是「字面有没有」，不查「是不是同一回事」**。原稿写「30 到 60 分钟」，口播写「接下来 60 秒」也能过；这类语义偷换还得靠人。
- **英文按字母计数偏严**。「MySQL 的 TIMESTAMP」14 个字母算 14 个字，念出来远没这么长，所以 `y2038-v2` 的镜头 8 会收到一条偏快警告。宁严勿松，保持原样。
- **中文数字只能告警不能溯源**。想让机器查得全，就让模型用阿拉伯数字（提示词 v2 第 6 条）。
- `run.py` 只放行 http/https，且会在发请求前解析接口主机，拒绝本机、环回、私有和保留地址。想接本地模型，请走路线 B。

## 目录

```
prompts/v1.md, v2.md     提示词模板（{{SOURCE}} 处填原稿）
sources/coffee.md        示例原稿：咖啡因 6 个数字
sources/y2038.md         示例原稿：2038 年问题（数字密度高，专门用来为难模型和审计器）
run.py                   调模型 + 解析 + 审计；也支持 --print-prompt / --from-response
verify.py                审计器，可单独使用，可 import
audit_all.py             复验 runs/ 下全部记录（CI 用）
runs/<date>-<slug>/      每次运行的提示词、原始回复、shots.json、审计报告、meta.json
tests/test_verify.py     审计器自测：把好分镜逐项改坏，确认每项检查都抓得到
```
